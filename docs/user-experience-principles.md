# User Experience Principles

## Quiet Time

Fluel should feel quiet. The product language repeatedly uses quietness,
gathering, reading back, and keeping time.

The user should feel that Fluel is preserving something gently, not pushing
them to optimize behavior.

## Ordinary Things Matter

The product should respect everyday objects and places without making them
overly dramatic. Wallets, bags, shoes, watches, notebooks, plants, furniture,
and homes are the reference objects.

The experience should make ordinary continuity visible.

## Begin Small

The first action should be easy:

Add one thing or place.

The user should not need to complete a large setup, create categories, or
understand every feature before getting value.

## Accept Imperfect Memory

Users often know only the month or year something started. Fluel should support
that honestly.

The product should:

- Let the user choose the precision they know.
- Label approximate starts.
- Avoid fake exactness.
- Allow later refinement.

## See The Whole Shape First

The product should help users understand the overall collection before diving
into details.

Important overview ideas:

- Current active count.
- Archived count.
- Longest-running active entry.
- Upcoming milestones.
- Recent activity.
- Monthly timeline trends.

## Keep Actions Close

Common next actions should be close to the user's context. Detail should make
share, duplicate, edit, archive, and restore readily available.

The goal is not to expose every option everywhere. The goal is to keep the next
natural action close when the user is already thinking about that entry.

## Preserve Separation Between Present And Past

Active entries are still with the user. Archived entries have moved out of
daily life.

The experience should make that distinction clear without making archived
entries feel erased or unimportant.

## Use Gentle Empty States

Empty states should explain what will gather there after the user begins.

They should invite the next small action rather than scold the user for missing
data.

## Support Scanning

Lists, dashboard, timeline, and widget surfaces should be easy to scan.

Support scanning through:

- Strong entry titles.
- Concise elapsed time.
- Metadata badges for notes, photos, and approximate starts.
- Summary cards when useful.
- Filters and search when the collection grows.

## Let Users Control Density

Some users may want more supporting metadata; others may want a quieter list.

Display preferences should preserve this user control.

## Confirm Quietly

When the user changes low-risk state, such as preset pinning, default preset
selection, display preferences, or hint visibility, Fluel should provide clear
non-blocking confirmation.

## Make Glances Useful

The widget-style surface should be passive and useful at a glance. It should
not require interaction to provide value.

The most important glance is the longest-running active entry and its time
together.

## Avoid Product Drift

Do not rebuild Fluel as:

- A home inventory manager.
- A warranty tracker.
- A collection valuation tool.
- A habit streak app.
- A countdown app.
- A social memory journal.
- A task manager.

Those directions may share vocabulary with Fluel, but they are not the
preserved product intent.
